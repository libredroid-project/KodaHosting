# Plan: Join-Adresse-Rework, Forge-Sperre, Fabric-Versionen & Modpack-Downloader

## 1. Join-Adresse ändern: Schritt-Animation + Voll-Rollback (ServerDetailActivity)

**Neues Layout `dialog_join_address.xml`** (Praetor-Style, eigenes Layout statt dialog_praetor_input, damit andere Dialogs unberührt bleiben):
- Titel + Message
- **Domain-Toggle über dem Eingabefeld** — exakt der Sliding-Pill-Toggle aus der CreateServerActivity (`container_domain`/`pill_domain`/`wrapper_*`/`btn_*` inkl. 200ms-Pill-Animation + Haptik), wiederverwendet als include oder geklont; initial = aktuelle Server-Domain
- Eingabefeld mit statischem Suffix `.{domain}`
- **Schritte-Panel** (initial unsichtbar, 4 Zeilen mit Status-Icon): ① Alte DNS-Einträge löschen ② Neue DNS-Einträge erstellen ③ Datenbank aktualisieren ④ Fertig — Icons animieren: Spinner → ✓ (mit Pop-Scale), Fehler → rotes ✗

**Ablauf nach Confirm** (Eingabe+Toggle blenden aus, Schritte blenden ein):
1. `deleteDnsLink(old, oldDomain)`
2. `createDnsLink(new, newDomain, target, port)` (nur wenn Playit/Tunnel existiert)
3. `patchServerHostInSupabase(old, new, newDomain)`
4. Bei Erfolg: lokales Repo-Update + Cooldown + Erfolgsmeldung

**Rollback bei jedem Fehler** (in umgekehrter Reihenfolge, mit „Änderungen werden zurückgerollt…"-Status):
- DNS-Erstellung fehlgeschlagen → alte DNS wiederherstellen
- DB-Patch fehlgeschlagen (Return false oder HTTP ≥ 400) → neue DNS löschen + alte wiederherstellen
- Lokales Repo wird erst NACH Schritt 3 geschrieben → nichts lokal zurückrollen nötig
- Fehleranzeige mit **Error-Code** (HTTP-Code + API-Fehlermeldung, z.B. „Fehlgeschlagen (Code 429): Rate limit… Alle Änderungen wurden zurückgenommen.")

`handleDnsOccupied` nutzt dasselbe Schritte-System ohne Domain-Toggle.

## 4. Modpack-Downloader für Fabric (das große Feature)

**Einstieg in CreateServerActivity:**
- Bei `type == FABRIC`: Setup-Sektion sichtbar, RadioGroup versteckt, stattdessen neuer **„MODPACK"-Button** (`btn_modpack`, orange hervorgehoben: 12dp-Ecken, `#FF6B00`-Stroke + Glow-Drawable, pulsierende Aufmerksamkeits-Animation) + Label darunter (`tv_modpack_selected`, zeigt gewähltes Pack)
- Klick: `HapticUtil.forceVibrate(this, 80)` + **Button-zu-Fullscreen-Animation**: Fullscreen-Overlay (FrameLayout in `android.R.id.content`) startet skaliert/transparent an der Button-Position und expandiert mit DecelerateInterpolator zu 100%

**Fullscreen Modpack-Browser** (programmatisch + neues Item-Layout, Koda-Dark-Design):
- Header: Titel „MODPACK DOWNLOADER" + X-Cancel-Button
- Suchleiste (EditText + Search-Button, imeOptions actionSearch)
- RecyclerView mit Ergebnissen (Icon via `ModrinthHelper.loadIcon`, Titel, Author, Beschreibung, Downloads) — **20 pro Seite** via `limit=20&offset=n`, „Mehr laden"-Footer wenn `total_hits > offset+20`
- Suche: `GET /v2/search?facets=[["project_type:modpack"],["categories:fabric"]]&index=downloads|relevance` (User-Agent `KodaNetwork/3.0` wie ModrinthHelper)
- **Pack auswählen** (Tap):`GET /v2/project/{id}/version?loaders=["fabric"]` → neueste Version, primäre `.mrpack`-Datei + `game_versions[0]`; wenn die MC-Version von der aktuell gewählten abweicht → automatisch `selectedVersion` + Anzeige updaten; dann **verschließt sich das Overlay mit umgekehrter Animation** zurück zum Button, der Button zeigt jetzt den Pack-Namen
- Cancel-Button: schließt ohne Auswahl (gleiche Collapse-Animation)

**Installation (`util/ModpackInstaller.java`, neu) — läuft beim Server-Erstellen im Executor, bevor zur Detail-Seite navigiert wird** (Progress über bestehendes loadingOverlay/„Lade Modpack… (n/m Mods)"):
1. `.mrpack` herunterladen (SHA-1 verifizieren)
2. `modrinth.index.json` parsen: `dependencies.minecraft`/`fabric-loader`, Files-Liste
3. Pro File: Pfad-Sicherheitscheck (kein `..`, kein absoluter Pfad — Zip-Slip-Schutz), `env.server != "unsupported"` respektieren, von `downloads[0]` laden, SHA-1 prüfen, nach `<serverDir>/{path}`
4. `overrides/` dann `server-overrides/` über das Server-Verzeichnis entpacken (ZipUtils.unzip hat bereits Zip-Slip-Schutz), `client-overrides/` skippen
5. Bei Fehler: aufgeräumte Fehlermeldung (lokalisiert), Server-Erstellung bricht ab
- Der normale Fabric-Server-Launcher läuft wie gehabt über JarDownloader (Version kommt aus dem Pack)
